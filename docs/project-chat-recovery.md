# 项目聊天无响应修复（2026-10-13）

## 根因

- 登录账号没有显式选模型时，默认取注册表第一项 `mdl_local`，已配置且有权限使用的 Qwen 未被选中。
- 模型返回的 `summary` 没有保存到 Task 或 `task.plan_ready`，正文在后端丢失。
- 正文、状态和审批入口没有独立展示，批准按钮嵌在默认折叠的思考卡内。
- 生成请求没有等待提示；失败仅显示短暂 toast；执行中的文件写入和验证输出未进入聊天。
- 响应校验强制要求非空 thinking/steps，删去这些字段会阻断有效补丁。

## 修复行为

保留用户显式选择的可用模型。未选择或原选择不可用时，优先选择当前账号有权限使用、已启用且具备地址和密钥的远程模型。没有配置模型时明确显示演示模式；显式选择但配置不完整的远程模型直接报错，不再偷偷切换演示模式。

Task 和计划事件保存正文；思考和步骤可缺省，但代码生成仍必须包含有效补丁，并继续执行路径、原文件哈希和设计契约检查。历史 Task 缺少正文时使用兼容默认值。

聊天立即显示等待消息，随后在同一位置展示正文、状态和独立审批按钮。详情继续默认折叠。失败提示保留在原工程对话中；执行展示文件路径、验证命令、退出码和结果。并发请求、切换工程及轮询重试仍绑定原任务，不会自动批准或重复执行。

## 验证

- 98 项 Python 回归测试通过，含登录账号默认模型路由、缺少思考字段的 HTTP 生成与执行、未批准不写入目标源码、正文持久化及无权限模型隔离。
- 4 组前端脚本通过，含慢请求提示、错误留存、正文与按钮位于折叠区外、事件去重和跨工程隔离。
- 使用真实 DOM 解析前端 HTML/CSS：详情关闭时正文和按钮在外部，消息纵向排列，点击批准后显示终态与执行结果。
- 真实 Qwen 3.8 Max + H2 登录：账号未选择模型时自动使用 Qwen；返回 0 个 thinking、0 个 steps 和 2 个代码补丁；审批前目标源码不存在；审批后生成 Calculator 和 unittest，任务成功。生成测试和独立验收均通过，仅消耗 1 次调用。

结果见 `benchmarks/reports/chat-recovery-2026-10-13.json`。源码读取后的索引文件属于上下文准备，不计作生成的目标源码。

## 发布核验与回退

使用独立 release 目录部署；发布前检查没有执行中任务，保留上一版本。发布后检查 daemon/agent 健康、前端资源版本、未登录请求仍返回 401，以及现存账号的默认模型选择。检查失败则切回上一个 release 并重启服务。

历史演示任务没有实际补丁，不能在升级后恢复为真实生成结果；应刷新页面并重新提交需求。此次不自动批准或重跑历史任务。
