# 大任务生成、技术栈推荐与界面精简

## 用户行为

- 项目聊天提交后立即返回后台任务，显示当前阶段、已完成文件数和用时。浏览器刷新、切换项目或短暂断网不会终止后台生成。
- 大任务先生成文件清单和接口契约，再逐文件生成。每个请求只输出一个文件，降低一次输出整个项目引起的超时和截断概率。
- 当前批次遇到可重试的请求错误或输出契约错误时最多尝试 3 次。失败后保留已完成文件，显示“继续生成”。恢复时复用已完成批次，不自动批准、写入或执行代码。
- 服务重启后，未完成任务标记为中断，可手动续跑。若工程内容或模型配置已改变，则重新规划，避免使用过期补丁。
- 技术栈按已有工程、用户明确选择、插件关键词和业务意图匹配顺序选择。教务/管理类后端推荐 Spring Boot，交互页面推荐 Vue，自动化脚本推荐 Python。
- 模糊需求或同时提到多种技术栈时，通过网页内弹窗给出推荐并确认；不再因为多个插件命中而直接报错。当前一次任务仍绑定一个工程插件，前后端组合建议分成独立项目。
- 已移除右侧“相关产物”下面的工程结构、文档产物、运行服务三个重复入口；工程主导航继续提供这些功能。

## 实现与边界

`GenerationService` 使用 4 个后台工作线程，最多接收 8 个排队或运行中的任务。任务与检查点保存在数据目录 `generations.json` 中，按用户、项目隔离；接口不返回内部检查点。正在排队或生成的项目不允许删除。

`ProjectGenerator` 每轮最多规划 48 个文件，单次输出最多 6000 tokens，并受所选模型输出配置限制（下限 1024）。生成上下文包含完整文件契约、已有源码上下文，以及最多 48000 字符的已生成依赖代码；构建声明优先保留。文件路径、补丁操作、原始内容与最终整体设计均需通过现有校验。

规划提示要求声明所有外部类型的依赖来源，并统一构造器、异常类型和测试接口；后续生成优先遵循实际已生成代码。此约束不能代替编译与行为测试。用户审批后仍由现有 Agent 执行插件的工程验证命令，编译失败会如实报告，不会被标记为成功。

后台分批模式在每次真正发起模型请求前扣除 1 积分，重试同样计费，复用缓存的文件不重复扣费。队列或模型并发额度不足、余额不足时不发起模型请求。大任务通常需要“规划 1 次 + 文件数”次调用，发生重试时更多。

技术栈推荐目前是插件声明驱动的关键词/业务意图评分，不是独立模型分类器。禁用插件不会被绕过，已有工程也不会被自动切换技术栈。

分批能降低单次超时概率，但不能保证供应商永不超时，单个文件过大仍可能需要缩小需求。整体设计检查失败的草稿会失效并重新规划。暂未提供生成阶段的取消接口；已有执行任务的取消机制保持有效。此工作队列面向单 daemon 部署，非分布式队列。

## API

| 请求 | 行为 |
| --- | --- |
| `POST /api/workspaces/{id}/recommendation`，`{goal}` | 返回推荐插件、理由、可选插件及是否需确认 |
| `POST /api/tasks`，增加 `async_generation: true` 和可选 `plugin_id` | 返回 HTTP 202 及后台生成任务 |
| `GET /api/generations/{id}` | 返回状态、阶段、文件进度；完成后返回待审批任务 |
| `POST /api/generations/{id}/resume` | 恢复当前用户的失败或中断任务 |
| `GET /api/conversations?workspace_id=...` | 同时返回可恢复的后台生成任务 |

旧同步创建任务 API 保持兼容。新前端统一使用异步生成路径。

## 验证记录（2026-10-14）

- 自动化覆盖：请求提前返回、跨用户拒绝访问、生成期间拒绝删除、瞬时错误重试、持久检查点与重启恢复、余额扣减、缓存复用、危险路径拒绝、依赖上下文预算、推荐与确认。
- 浏览器覆盖：进度、切换项目、续跑、刷新恢复、推荐选择/取消、旧计时动画、成功/失败/取消整轮折叠、网页内确认框，以及重复入口移除。
- 在服务器隔离目录使用实际配置模型生成 Spring Boot 教务后端：23 个文件，首次生成约 350 秒，无单次请求超时。首次 Maven 编译发现未声明的 JPA 异常依赖；一轮模型修复修改 3 个文件，生成和验证约 71 秒。未删除或跳过测试，最终 19 个 Maven 测试通过。
- 在修复后的工程启动真实 HTTP 服务，另行执行 12 项独立接口检查：学生/课程创建、缺失对象 404、未选课成绩 400、重复选课 409、分数上下界、成绩写入与读取、空姓名校验，全部通过。
- 实测失败促使生成约束补充依赖来源、接口一致性和构建文件上下文优先级。该记录包含首次失败及后续修复，不代表所有工程都能首次生成成功。

## 发布与回退

先在隔离目录验证，再检查线上无活跃生成/执行任务，备份 JSON 与 H2，切换独立发布目录。发布后检查健康、前端静态文件及未登录访问限制，并比对账户、会话、余额、项目和任务数据。失败时切回旧代码，不使用旧备份覆盖新产生的用户数据。`generations.json` 为新增数据文件，不改变旧任务或账户结构。
