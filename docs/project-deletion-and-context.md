# 项目删除与对话上下文窗口

## 项目删除

项目设置底部提供红色「删除项目」按钮。第一次说明影响并确认继续；第二次必须输入完整项目名称。取消、名称不符、切换项目或退出账户都不会提交删除。

`POST /api/workspaces/{id}/delete` 接受 `confirmed: true` 和 `confirm_name`。它转为标准工具 API 的 `workspace/delete`；后端再次校验身份、名称和确认值。用户只能删除自己的项目。

本次采用保留文件的删除：原项目从活动列表移除，源码、产物文件、对话、任务与事件保留为存档。原项目 ID 不再允许读取、下载、修改、启动或审批任务；没有自动恢复页面。同一用户可重新添加原目录，但会创建新的项目 ID，不自动恢复旧会话。此功能不用于释放磁盘或永久擦除数据。

Web 与 Agent 使用按项目划分的跨进程文件锁，协调模型生成、审批、工具调用、配置修改和删除。正在生成、执行任务、执行工具时拒绝删除；运行中的服务必须先停止。删除先把原项目记录写入 `deleted_workspaces.json`，再原子移出 `workspaces.json`；写入失败时活动记录保留。删除存档继续保护原目录，其他账户无法据此认领其文件。确认名称以服务端已保存项目名称为准。

## 上下文

自由聊天和项目生成均使用 `ConversationService.context`：每次请求携带最近 15 轮历史原文，再附上本次消息；一轮定义为一次用户需求及对应回复/任务状态，不按工具事件条数计数。完成后超出 15 轮的部分生成持久摘要，完整 UI 历史仍保存在原记录中。

`conversation_archives` 按用户 ID 和项目 ID 保存；自由对话使用空项目 ID，与项目对话隔离。生产存入 H2。摘要在本地提取需求、回复/方案、真实执行状态、错误及相关文件路径，不再调用模型，不扣额外积分。待审批方案不当成已执行结果；后续任务状态变化会在下一次读取上下文时刷新摘要。

模型上下文不传旧补丁全文、思考块或执行日志。单条归档摘要有长度上限，送给模型的总摘要最多 12,000 字符。极长会话保留首轮要求和最近归档摘要，并明确告知中间摘要省略、信息不足时需询问；所有逐轮摘要和原始历史仍持久保存。此策略是有损的本地提炼，不保证超长历史中的所有细节持续可见。

## 验证与发布

- 15/16 轮边界、120 轮摘要大小、重启后恢复、重复刷新幂等。
- 用户/项目/自由对话隔离、已归档任务晚到失败状态更新。
- 实际模型请求包含 15 轮历史与摘要，项目生成链路同样生效。
- 两次确认、错误名称、无权限、生成/工具执行期间删除被拒、运行服务拦截。
- 真实浏览器的取消、输入校验、切换项目、删除后列表和会话缓存清理。
- 真实 daemon + 独立 Agent + H2：服务停止后可删除，退出登录/重启不复活，源文件保留，归档持久且不额外扣费。

发布使用独立 release、保留上一版本及 H2/JSON 备份，确认没有活动请求后切换。新增存储为独立集合/文件，没有修改现有 Workspace/Task 数据结构。旧版本可读取剩余活动项目，但回退代码会失去删除目录预留保护和 15 轮窗口能力；若要求保留这两项，需向前修复。不得在已接收新请求后直接恢复旧数据备份，以免丢失新对话/计费。立即部署验证失败时才允许在维护窗口恢复备份。
