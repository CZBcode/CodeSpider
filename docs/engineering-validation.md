## 实测发现与修改

第一轮三个工程均在设计契约校验阶段被拒绝，不能报告为首轮 3/3。分析后先修复检查器，再重放相同模型输出，最后对实际实现问题发起新的模型修复请求：

1. **空包标记被要求描述独立职责**：Python 的空 `__init__.py` 不承担业务职责，已排除；含导入、赋值或函数的初始化模块仍检查。
2. **设计说明格式过窄**：模型用对象描述参数、数组描述异常，比一段字符串更清晰。接口说明现在支持有界结构化值，空错误数组有效，路径和符号仍严格检查。
3. **符号识别漏项**：Java 接口方法可省略 `public`，Vue SFC 具有隐式组件名。补齐这些证据，避免误判“接口不存在”。仍明确标注 Java/Vue 使用词法分析。
4. **Spring 测试装配失败**：模型在测试配置中重写了应用同名 Bean，还复制了定价算法作为替身。后续模型仅修改测试配置，采用真实 Spring Boot 上下文与 MockMvc，保留原有 HTTP 断言和业务单测。业务实现未修改，最终通过。
5. **旧文件回显不可靠**：第一次 Spring 修复连续三次输出的 expected 均比原文件少一个末尾换行。新增 `file_hashes` 与 `base_sha256`，由网关验证哈希并补全原文，Agent 仍精确比对；下一次模型修复成功。
6. **Vue 产品契约不一致**：组件假设产品有未保证的 `name` 字段，合法 `{id,priceCents}` 输入显示空名称。模型补充 `name || id` 回退，并将无错误状态统一为空字符串，保留最新请求获胜和实例隔离。
7. **测试器自身也需要校准**：Python 原需求要求拒绝非法类型，但未统一规定必须是 ValueError；生成接口明确 TypeError，独立验收改为接受两种明确错误。Vue 原验收错误地要求成功状态也有重试按钮；改为制造网络失败、点击错误态重试、验证产品展示。无错误时使用空字符串属于本轮明确补充的接口约定。这些修正记录在报告中，没有将测试器误报描述成实现缺陷。

前三例最终完整重放：3/3。第四例使用最新的源码结构上下文和哈希补丁进行新的真实模型调用，一次响应通过生成测试、独立验收与原文件保护检查，合计最终 4/4。第四例只修改 `shop/pricing.py` 并新增 `tests/test_capped.py`，既有服务、协议、仓储、入口与旧测试共 5 个文件逐字不变，验证开闭原则与策略可替换性。npm 自动生成的锁文件不会被伪装成模型补丁；锁文件随可运行示例保存。最终设计说明合并初始模型设计与修复声明，源码结构报告独立重新计算。

## 反向结构验收

在最终源码的内存副本中故意引入以下违规，不修改交付示例：

- Python 的 `shop/service.py` 反向依赖组合入口 `main.py`：触发禁止依赖及循环。
- Spring 的 Controller 直接导入 Repository：触发 Web→Repository 越层依赖。
- Vue 的 App 直接导入 API Service：触发 View→API 越层依赖。

三例全部被 enforce 规则阻止。另有系统回归验证：规则变更后拒绝旧任务、违规补丁在任何写入前被拒绝、非法契约失败关闭、分析不完整不能获得强制通过、源码哈希不匹配不能覆盖、注释与字符串不误报导入、源码中的真实符号必须与设计声明一致。

## 系统回归与限制

93 项 Python 单元/集成/daemon 回归、4 组前端脚本全部通过。前端覆盖审批、安全模式源码确认、工程隔离、设计与结构的转义展示；工程示例的测试与这些系统测试分开统计。

执行环境沿用隔离的 Node 22、Maven 设置与 npm registry；JDK 26 编译目标 17。测试验证了这些限定需求，不是复杂工程通用生成成功率，也不证明“高内聚”语义或所有设计模式都能自动判定。详细解析范围、预算、模式开关与工具契约见 `docs/design-contracts.md`。
