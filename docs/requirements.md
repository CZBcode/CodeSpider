# 代码工程 Agent 系统需求文档

**版本**：v0.1  
**状态**：需求基线  
**目标读者**：产品、架构、前端、后端、Agent、测试与安全团队

## 1. 项目概述

本系统是一套面向代码工程的 Agent 工作台，产品形态参考 Cursor、Claude Code、Codex 等成熟工具，提供“用户提出目标—Agent 理解工程—修改文件—执行验证—反馈结果”的完整闭环。

系统由两部分组成：

1. **交互前端**：用户输入需求、浏览工程文件和代码结构、查看 Agent 执行过程、运行代码并查看效果、管理本地部署、生成文档。
2. **Agent Client 与执行后台**：在用户授权的工程工作区内读取和修改文件、分析代码、执行命令、采集结果、调用模型和工具，并以事件流方式向前端反馈。

首期支持三类工程：Java Spring Boot、Python、Vue。设计上通过工程适配器保留扩展到其他语言和框架的能力。

### 1.1 安装与运行交互

用户下载后通过命令行启动系统。CLI 启动后台 daemon，daemon 启动前端 Web 服务与独立 Agent Client，用户通过浏览器访问本机 8787 端口进行控制。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-INSTALL-01 | 下载源码可通过 `python3 -m codespider start` 启动，安装后可使用 `codespider start` | P0 |
| FR-INSTALL-02 | daemon 管理 Web 与 Agent 的启动、就绪检测和停止；终端关闭后继续运行 | P0 |
| FR-INSTALL-03 | 默认访问 `http://127.0.0.1:8787`；支持启动完成后自动打开浏览器 | P0 |
| FR-INSTALL-04 | 提供 start、stop、restart、status、logs；重复启动不创建重复实例 | P0 |
| FR-INSTALL-05 | 端口冲突或启动失败给出可定位日志并清理本次启动的子进程 | P0 |
| FR-INSTALL-06 | 停止/重启保留项目、记忆和模型设置；停止时清理 Agent 启动的工程服务 | P0 |
| FR-INSTALL-07 | 本期支持 macOS/Linux、Python 3.9+，不要求 Node 或外部数据库 | P0 |

当前版本不提供操作系统开机自启动，不自动恢复被中断的任务。用户可在浏览器中管理工程运行；系统本身的生命周期由 CLI 控制。

## 2. 产品目标

### 2.1 目标

- 让用户用自然语言完成需求分析、代码修改、测试、运行和文档生成。
- 让 Agent 具备可观察、可暂停、可恢复、可审计的执行过程。
- 让代码理解建立在 AST、符号和依赖关系之上，减少仅凭全文上下文生成代码造成的错误。
- 用分层记忆持续积累当前任务、项目配置、个人偏好和可复用经验。
- 在本地工程和远程模型之间建立明确的权限边界，默认保护源代码、密钥和系统环境。

### 2.2 非目标

- 首期不替代完整的 IDE 调试器、商业 CI/CD 平台或生产发布平台。
- 首期不允许 Agent 在未授权情况下访问任意文件、执行高风险命令或修改生产环境。
- 首期不承诺对所有语言提供同等深度的语义分析；先保证 Java Spring Boot、Python、Vue 的核心场景。

## 3. 用户与典型场景

### 3.1 用户角色

| 角色 | 主要诉求 |
| --- | --- |
| 开发者 | 快速理解已有工程、实现需求、运行验证、减少重复操作 |
| 技术负责人 | 评审变更、掌控权限、查看任务记录和质量结果 |
| 初级开发者 | 获取分步解释、生成测试和文档、降低工程上手成本 |
| 运维/交付人员 | 在受控环境中启动、停止和检查本地或测试部署 |

### 3.2 典型场景

1. **理解工程**：打开项目后，系统识别工程类型，构建文件树、模块图、接口和函数索引；用户询问“登录流程在哪里实现”。
2. **实现需求**：用户提出“增加订单导出接口”，Agent 先给出计划，用户批准后修改代码、生成测试并运行。
3. **修复问题**：用户贴出错误日志，Agent 定位调用链、读取相关函数和配置，提出补丁并验证。
4. **运行查看效果**：用户要求启动 Vue 前端和 Spring Boot 后端，系统分配端口，展示终端日志和可访问地址。
5. **生成文档**：根据当前代码和变更生成 README、接口文档、部署说明或变更记录。
6. **复用经验**：用户确认一个高质量解决方案后，将其沉淀为项目 Skill，后续任务可检索和调用。

## 4. 产品原则

- **先理解再修改**：在大范围修改前，Agent 必须展示工程范围、计划和预期文件。
- **用户可控**：高风险操作需要明确授权；用户可以暂停、取消、回滚和重试。
- **过程透明**：每个读取、写入、命令、模型调用和结果都可追踪。
- **最小上下文**：按任务检索必要代码，避免把整个工程无差别交给模型。
- **结果可验证**：代码变更应尽可能配套测试、静态检查或运行结果。
- **记忆可治理**：记忆可查看、修改、禁用、删除和设置过期时间。

## 6. 前端需求

前端建议采用三栏工作台：

- **左栏**：工作区、文件树、搜索、符号和服务列表。
- **中栏**：代码编辑器、差异视图、任务计划和执行详情。
- **右栏**：对话、审批卡片、终端、预览和文档生成结果。

必须提供以下交互：

- 输入框支持自然语言、`@文件`、`@符号`、`@任务` 和拖拽日志。
- 文件修改以 Diff 形式显示，支持全部采纳、逐文件采纳、拒绝和回滚。
- 长任务显示阶段、当前工具、已修改文件、资源使用和取消按钮。
- 命令执行显示命令、工作目录、环境摘要、实时输出、退出码和风险级别。
- 所有高风险审批卡片说明“将做什么、作用于哪里、可能影响什么”。

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 首个任务事件在 2 秒内返回；文件树和符号索引支持 10 万级文件；常用增量索引在 5 秒内完成 |
| 可用性 | 任务事件断线后可恢复；后台任务状态不依赖浏览器页面存活 |
| 安全 | 工作区越界访问拦截；命令分级审批；敏感信息脱敏；密钥不写入模型上下文和日志 |
| 可观测性 | 记录任务、工具、命令、模型、文件差异、耗时、退出码和错误分类 |
| 可维护性 | Agent 工具、工程适配器、模型供应商和存储实现可插拔 |
| 可测试性 | Agent 计划、工具授权、补丁应用和 AST 索引均可独立测试 |
| 国际化 | 首期中文界面，数据模型保留中英文消息字段 |

## 8. 安全与权限需求

系统提供两种执行模式：

- **安全执行模式**：命令执行、工程文件内容读取、文件写入和本地服务启动默认需要用户确认；用户可以配置命令白名单，使经过确认的常用命令自动放行。路径越界和禁止命令始终拒绝。
- **发散模式**：允许低风险和普通开发命令直接执行，只有高危命令、破坏性操作和越界访问需要确认；禁止命令仍然拒绝。

两种模式都支持只读、工作区写入、可执行命令和部署控制等权限等级。模式属于项目配置，任务执行时继承项目模式，单次用户确认只对当前操作生效。

以下行为必须二次确认或进入显式审批：删除或批量覆盖文件、访问工作区外路径、安装依赖、网络访问、读取疑似密钥、修改 CI/CD 或部署配置、启动长期运行进程、执行数据库写操作。

系统必须提供敏感文件默认规则（例如 `.env`、私钥、云凭证、生产配置），并支持用户增加规则。日志和模型请求中的密钥、Token、银行卡号等信息必须脱敏。

## 9. 验收标准

MVP 至少完成以下闭环：

1. 打开一个 Java Spring Boot、Python 或 Vue 工程并完成类型识别。
2. 用户提出一个小型代码需求，Agent 生成计划并等待批准。
3. Agent 读取相关文件、生成补丁、展示 Diff，用户采纳后写入文件。
4. Agent 执行配置的测试或构建命令，前端展示实时输出和退出结果。
5. 用户可以暂停或取消任务，刷新页面后仍能看到任务状态。
6. 系统能通过 AST 索引定位至少一个类/方法/函数/组件及其引用。
7. 系统能保存短期上下文、项目配置记忆和个人偏好，并在下一次任务中检索。
8. 用户确认一个解决方案后可以保存为 Skill，并在相似任务中看到推荐。
9. 系统生成一份带代码引用的 Markdown 文档。
10. 越权路径、未授权危险命令和敏感信息泄露测试通过。

## 10. 分阶段交付

### Phase 1：可用闭环（MVP）

工作区管理、对话任务、计划审批、文件读写、Diff、命令执行、事件流、基础 AST 索引、短期/中期记忆、Markdown 文档生成。

### Phase 2：工程化增强

任务恢复、Git 隔离分支、Skill 管理、个人偏好、依赖图、服务预览、Docker Compose、权限策略和审计台账。

### Phase 3：高级智能

跨语言调用图、并行子 Agent、自动回归测试、评测集、团队共享记忆、多模型路由和远程执行节点。
